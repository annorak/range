# Step 4.3 — Model-trace capture from Inspect  `[MVP]`

> **Claude Code session prompt.** Self-contained. Read
> `docs/steps/_SHARED_STANDARDS.md` first.

## Session context

The trace store persists `Event`s (4.2) and the attacker agent runs via Inspect
(3.2). This step bridges them: turn **Inspect's transcript/event stream** into
unified `ModelEvent`s — reasoning, each tool call + result, compaction boundaries,
and per-call token usage — written to the `TraceStore` with correct
`agent_id`/`step_seq`. This is half of "one timeline" (host telemetry, 4.4, is the
other half). Capture is **read-only on Inspect** — it must not perturb the run.

## Goal

Every agent action appears as a correlated `ModelEvent` on the timeline.

## Scope (build this)

- `trace/model_capture.py`: subscribe to Inspect's live event hooks (preferred) or
  post-process the `.eval` log (fallback) → emit `ModelEvent`s into the
  `TraceStore`, mapping Inspect tool-call IDs → `step_seq` and feeding token usage
  into cost (§8).

## Out of scope

- Host capture (4.4); network capture (4.5); query/replay (4.6); the agent itself
  (3.2).

## Deps introduced this step

None (uses `inspect-ai` from 3.1, `trace` from 4.1/4.2).

## Implementation details

> Conform to the **pinned Inspect version's** event/hook API (3.1, ADR 0006). The
> shapes below are intent — match the installed package; if hooks are insufficient,
> use the log-parse fallback and document which in ADR 0009.

- **Capture mechanism** (prefer streaming):
  - *Live hooks*: register an Inspect event subscriber/hook that fires on
    reasoning steps, tool calls, tool results, and token-usage updates; translate
    each to a `ModelEvent` and `TraceStore.append` it as the run proceeds (enables
    `--follow` in 4.6).
  - *Fallback*: after the eval, parse the `.eval` log into the same `ModelEvent`s.
  - Pick one as primary; keep the mapping logic shared so both paths produce
    identical events. Document the choice in ADR 0009.
- **Mapping**:
  - reasoning → `ModelEvent(kind="reasoning", text=...)`.
  - tool call → `ModelEvent(kind="tool_call", tool_name, tool_args[redacted])`;
    tool result → `ModelEvent(kind="tool_result", result_summary)`.
  - compaction boundary (from 3.2) → `ModelEvent(kind="compaction")`.
  - token usage → `ModelEvent(kind="token_usage", input_tokens, output_tokens)`;
    aggregate into the run's cost.
  - **Inspect tool-call ID → `step_seq`**: maintain a stable mapping so model
    events align with host/network events on the same step. Use the run's
    `LogicalClock` (0.2) for `(step_seq, source_seq)`.
- **Correlation**: every event carries the run's `CorrelationIds` with
  `agent_id` = the attacker role, `source="model"`.
- **Read-only / non-perturbing**: capture must not alter Inspect's control flow,
  prompts, or results; on a capture/store error, **log and continue** the run
  (never fail the eval because tracing hiccuped) — but record that a gap occurred.
- **Secrets**: tool args/results pass through the logging redaction shapes (0.2)
  before storage; never persist raw API keys.

## Infrastructure (Terraform)

- **None.** Capture is in-process on the control plane (the 0.3 host), reading
  Inspect and writing through the `TraceStore` from 4.2 (which already owns the
  Postgres/Parquet infra). No new OCI resource, no new egress/secret need. Runs in
  CI on the fake backend + mock model (no API spend).

## Contracts produced

Model events present on the timeline for **every** run — the input the scorer
(3.3), replay, and reports rely on.

## Testing

**Unit (fake backend + mock model — runs in CI):**
- Run the 3.2 attacker with a mock model returning canned tool calls; assert the
  emitted `ModelEvent`s match the model's tool calls **1:1** (reasoning, call,
  result, token usage), with **monotonic `step_seq`** and correct token totals.
- Compaction (3.2) produces a `compaction` event at the boundary.
- A forced `TraceStore.append` error mid-run is **swallowed** (run completes) and a
  capture-gap is recorded — capture never breaks the eval.
- Redaction: a tool arg containing a key-shaped string is redacted in the stored
  event.
