## Session context

The spec parses (1.1) and validates (1.2). This step makes two things real:
**how progress is scored** (milestone dependency DAG + sequential/independent
credit), and **composition** — specs assembled from reusable **fragments** via an
`includes:` mechanism, so authors don't hand-write every range from scratch.

This is the **scoring *spec***, not the runtime scorer. The pure credit functions
here are consumed later by the scorer (Step 3.3); fragments are consumed by spec
authors and the reference range.

milestone DAG**; credit semantics are pure, deterministic, and tested.

Credit semantics (pure, deterministic — the heart of scoring):
```python
class CreditResult(BaseModel):
    credited_milestones: list[str]
    score: float                        # 0.0–1.0, fraction of milestones credited

def compute_credit(
    milestones: Sequence[Milestone],
    scoring: Scoring,
    reached_flag_ids: Set[str],
) -> CreditResult:
    """Given which flags were captured, decide which milestones are credited.

    - A milestone is *directly met* when all its flags are in reached_flag_ids
      (or, with partial_credit, at least one flag).
    - sequential: meeting a milestone also credits all transitive `requires`
      (reaching a later objective implies the earlier ones).
    - independent: each milestone stands alone.
    score = len(credited) / len(milestones).
    """
```
> **Invariant to preserve (tested): monotonicity** — adding flags to
> `reached_flag_ids` never lowers `score` or removes a credited milestone.

### `spec/fragments.py`
A fragment is a **parameterized partial scenario** that contributes hosts /
services / identities / milestones. Keep it data, not code.

```python
class Fragment(BaseModel):
    name: str
    description: str
    params_schema: dict[str, Any]       # tiny JSON-schema for its params
    def apply(self, params: Mapping[str, Any]) -> dict[str, Any]:
        """Return a partial scenario dict (merged into the base before validation)."""

def merge_fragments(
    base: dict[str, Any], includes: Sequence[Mapping[str, Any]]

    """Deep-merge each resolved fragment into `base`.

    - Disjoint keys: order-independent (the result is identical regardless of

    - Overlapping/conflicting keys: emit `spec.fragment.conflict` and do not
      silently overwrite.
    Lists of named objects (hosts, subnets, milestones) merge by `name`/`id`.
    """
```

### `spec/loader.py` (extend)
- Before constructing `Scenario`, if the parsed YAML has a top-level
  `includes: [{fragment: <name>, params: {...}}, ...]`, resolve each via
  `FRAGMENTS`, call `apply(params)`, `merge_fragments` them into the base dict
  (which may itself add/override hosts etc.), collect any conflict diagnostics
  (raise `SpecError("spec.fragment.conflict", hint=...)` if any), then validate
  into `Scenario`.
- **`scenario_id` is computed on the merged, realized spec** — so the hash
  reflects the actual range, deterministically. Keep `load_scenario` pure (the
  registry is in-memory data).

## Testing

**Unit**
- *DAG*: a cyclic `requires` → `spec.milestone.cycle`; an unresolved `requires` →
  `spec.milestone.requires_unresolved`; a valid chain → empty + correct
  `topological_order`.
- *credit*: on a toy chain A→B→C (C `requires` B `requires` A): reaching only C's
  flag credits A, B, C under **sequential**, but only C under **independent**;
  `partial_credit` toggles partial milestones; `score` matches `credited/total`.
- *fragments*: each example fragment `apply`s to a valid partial; `merge_fragments`
  of disjoint fragments succeeds; conflicting fragments emit
  `spec.fragment.conflict`.
- *includes*: the refactored `mini-enterprise.yaml` loads and validates clean;
  the realized host set matches expectation.

**Property (hypothesis)**
- **Include-order independence**: for disjoint fragments, permuting the `includes`
  order yields an **identical canonical spec and identical `scenario_id`**.
- **Credit monotonicity**: adding flags to `reached_flag_ids` never decreases
  `score` nor un-credits a milestone.
