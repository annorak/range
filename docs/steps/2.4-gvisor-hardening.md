# Step 2.4 — gVisor runtime + isolation hardening  `[MVP]`

> **Claude Code session prompt.** Self-contained. Read
> `docs/steps/_SHARED_STANDARDS.md` first.

## Session context

Containers run and are networked (2.2/2.3), but on the default runtime with
default privileges — not safe for the **offensive/untrusted workloads** a range
runs. This step makes **strong isolation the default**: every range container runs
under the **gVisor `runsc`** runtime (installed on the 0.3 host) with
`no-new-privileges`, dropped capabilities (allowlist per host `role`), read-only
rootfs + explicit writable mounts, and resource/seccomp limits. CI usually lacks
`runsc`, so there is a **`runc`-with-hardening fallback** that is still tested.

## Goal

Every provisioned container is hardened; `runsc` is used wherever present; the
hardening (minus the runtime) is still verified on `runc` in CI.

## Scope (build this)

- Run containers under **`runsc`**, selected via config/profile (`prod`→`runsc`;
  `ci`→`runc`-with-hardening if `runsc` absent).
- Apply `no-new-privileges`, **dropped caps** (allowlist only what a role needs),
  read-only rootfs + explicit writable mounts, pids/ulimit/memory limits, seccomp
  defaults.
- A **`SecurityProfile` per host `role`** (capability allowlist + mount policy),
  overridable per host with a justification field.
- Graceful, clear error if `runsc` is requested but unavailable.

## Out of scope

- VM-level isolation (future backend); changing the network model (2.3).

## Implementation details

- **Runtime selection**: from `Settings`/profile. `runsc` for `prod`/`local`
  (where installed); fall back to `runc` for `ci` if `runsc` is absent, but
  **keep all the hardening**. Detect `runsc` availability via the Docker info
  runtimes list; if explicitly required and missing, raise
  `ProvisionError(code="provision.runsc_unavailable")` with a clear hint.
- **`SecurityProfile`** (per role): a capability **allowlist** (start from none,
  add only what the role's services need — e.g. a web host needs
  `NET_BIND_SERVICE`), `no-new-privileges: true`, `read_only` rootfs with named
  writable mounts (e.g. `/tmp`, a data dir), `pids_limit`, `mem_limit`, ulimits,
  and the seccomp profile (default). Per-role constants; per-host override carries
  a `justification` string.
- Map `SecurityProfile` → Docker `create` kwargs (`runtime`, `cap_drop=["ALL"]` +
  `cap_add=[...allowlist]`, `security_opt=["no-new-privileges"]`,
  `read_only=True`, `tmpfs`/`mounts`, `pids_limit`, etc.).
- Note the **gVisor `--net-raw`** consideration if any in-range tool needs raw
  sockets (e.g. some scanners): document in ADR 0005 and gate it behind the
  profile (don't enable globally).

## Infrastructure (Terraform)

- The host already has `runsc` (0.3 cloud-init). If this step needs **runsc
  runtime flags** (e.g. `--net-raw`, platform tuning) set at the daemon level,
  add them to `deploy/terraform/cloud-init/bootstrap.yaml`'s `daemon.json`
  (surgical) and `make tf-apply` to re-bootstrap — never hand-edit the host.
- Confirm via `docker info` that the `runsc` runtime is registered (the
  `make host-smoke` check from 0.3 already does this).
- `@pytest.mark.gvisor` tests run on the OCI host (they require `runsc`); they skip
  in GitHub CI, where the `runc`-hardening path is exercised instead.

## Contracts produced

Hardened defaults applied to **every** container; a `SecurityProfile` per host;
the runtime-selection policy.

## Testing

**Unit (`test_security.py`, runs in CI):**
- `SecurityProfile` → docker-arg mapping is correct for each role (caps dropped to
  `ALL` then allowlist re-added; `no-new-privileges` set; read-only + mounts;
  limits). Per-host override merges with a justification.

**Integration:**
- `@pytest.mark.gvisor` (OCI host): a container runs under `runsc`;
  `no-new-privileges` is enforced (a setuid-escalation attempt fails); a dropped
  capability blocks a privileged op.
- `runc`-hardening path (CI, no runsc): the same hardening assertions hold minus
  the runtime (caps dropped, no-new-privileges, read-only), proving CI still
  guards isolation.

## Engineering standards

All of `_SHARED_STANDARDS.md`. **Isolation is a default, not an opt-in** (§7/§8).
Capability allowlists start empty and add only what's justified. Document syscall
caveats in ADR 0005. Comment the *why* on `--net-raw` gating.
