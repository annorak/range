# Step 4.4 — Host telemetry capture  `[MVP]`

> **Claude Code session prompt.** Self-contained. Read
> `docs/steps/_SHARED_STANDARDS.md` first.
>
> ⚠️ **Highest-risk step in the trace layer.** Kernel-level tracing
> (eBPF/auditd) may be **constrained under gVisor (`runsc`)**. **Validate the
> chosen capture mechanism under `runsc` first**, and keep the documented fallback
> ready (log-tail + an exec wrapper). Don't discover the constraint late.

## Session context

Model events are on the timeline (4.3). This step adds **the other half of "one
timeline"**: what actually happened **on each host** — process exec, auth events,
file changes — captured by a lightweight per-host collector, shipped to the
control plane, normalized to `HostEvent`s in the `TraceStore`. This is what lets a
reviewer see *"the model ran X → which spawned process Y and touched file Z."*

## Goal

Model + host events appear **interleaved on one replayable timeline**.

## Scope (build this)

- `telemetry/host_collector/`: a **dependency-light** per-host collector capturing
  process exec, auth, and file events on Linux hosts, writing **NDJSON** to a
  host-local path; chosen for **container/gVisor compatibility**.
- `trace/host_capture.py`: the control-plane side — ingest the collector's NDJSON,
  normalize → `HostEvent`s, write to the `TraceStore`, correlate to `step_seq`.

## Out of scope

- Real EDR/Defender (future Windows/VM backend); network capture (4.5). v1 emits
  `edr_alert` events **only** from a *simulated* Linux EDR rule set **if** the
  scenario defines one.

## Deps introduced this step

Prefer **stdlib + the chosen tracer**. If a userspace tracer is needed, vendor a
minimal one; avoid heavy agent frameworks. Add only what the chosen mechanism
requires; record it in the ADR.

## Implementation details

- **Collector mechanism (gVisor-aware — decide and validate early):**
  - Candidates, in order of fidelity: a minimal eBPF/`execsnoop`-style tracer →
    `auditd`-lite / `fanotify` file watcher → **fallback**: tail `/var/log/auth.log`
    + an **exec wrapper** (PATH-shimmed or `ptrace`-based) for process events.
  - **Under `runsc`, kernel tracing is often unavailable** — so the realistic v1
    default is likely the **log-tail + exec-wrapper** path. Test the candidate on
    the OCI host **under `runsc`** before committing; record what works in ADR
    0010. Choosing the dependency-light fallback now is acceptable and expected
    (it's a "good enough for now" choice — note richer eBPF sensors as a future
    item; this aligns with backlog around fidelity).
  - The collector writes **NDJSON** to a host-local path; events tagged with
    `host_id`. The Docker backend (2.2/2.4) **injects/starts** the collector in
    each host (in-image or as a co-process) at provision and streams/mounts the
    NDJSON to the control-plane ingester.
- **Normalize → `HostEvent`** (4.1): `process` (pid/ppid/exe/argv), `auth`
  (user/success), `file` (path/op), and `edr_alert` (rule_id/severity) only from a
  scenario-defined simulated rule set.
- **Correlation**: tag with the run's `CorrelationIds` + `host_id`; correlate to
  `step_seq` by **wall-clock + run context** (host events aren't driven by the
  agent's step loop, so align by timestamp into the nearest step window; document
  the rule).
- **Security (critical):** collectors are **in-range / untrusted side** — they
  **only ship data out, never accept commands in**. No control channel into the
  collector; the ingester treats collector input as untrusted data (validate,
  bound sizes). This is a hard isolation property.

## Infrastructure (Terraform)

- **No new OCI resource.** The collector runs **inside range containers** (Docker
  level) and the ingester runs in the control-plane process on the 0.3 host;
  `HostEvent`s persist via the 4.2 `TraceStore` (block-volume Parquet / Postgres).
- **gVisor validation is the infra-adjacent risk:** run the
  `@pytest.mark.gvisor`/`docker` telemetry tests **on the 0.3 host under `runsc`**
  to prove the chosen mechanism works there. If a daemon-level capability is
  needed (it generally is **not** for the log-tail/exec-wrapper path), add it to
  `deploy/terraform/cloud-init/bootstrap.yaml` surgically and `make tf-apply` —
  never hand-edit the host. Do **not** weaken container hardening (2.4) to make
  capture work; pick a mechanism that lives within the hardened profile.

## Contracts produced

Host events on the timeline; the **collector contract** future richer sensors
(real EDR, VM-level) implement behind the same ingest path.

## Testing

**Unit (`test_host_capture.py`, runs in CI):**
- NDJSON fixtures → `HostEvent`s: process/auth/file lines map correctly, tagged
  with `host_id`; malformed/oversized lines are rejected (untrusted-input
  handling); `step_seq` correlation rule places events in the right window.

**Integration (`@pytest.mark.docker` / `gvisor`, on the OCI host under `runsc`):**
- A **known command** on a host produces the expected **process + file** events;
  an **auth attempt** produces an auth event; events land in the store with the
  correct `host_id`.
- **Interleave check:** after a short run, model (4.3) + host events reconstruct on
  **one ordered timeline** (this is the cross-step proof feeding 3.4/4.6).

## Engineering standards

All of `_SHARED_STANDARDS.md`. **Collectors are in-range and only ship data out —
never accept commands in.** Dependency-light; works within the 2.4 hardened
profile under `runsc`. Validate the mechanism early; document it + the fallback in
ADR 0010. Comment the *why* on the timestamp→step correlation and the
untrusted-input bounds.
