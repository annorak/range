# Step 2.5 — Golden-image build pipeline + vuln/flag injection  `[MVP]`

> **Claude Code session prompt.** Self-contained. Read
> `docs/steps/_SHARED_STANDARDS.md` first.

## Session context

Hosts run hardened, networked containers (2.2–2.4), but from whatever image the
spec names. A real range needs **purpose-built host images** that carry the
services, the planted vulnerabilities, and the scored **flags** — built
**reproducibly** (same inputs ⇒ same digest) so scoring is stable across runs.
This step builds that golden-image pipeline + the vuln/flag injection mechanism.

## Goal

The reference range builds reproducibly with correctly planted flags and a
working content-addressed cache.

## Scope (build this)

- `provision/images.py`: a build pipeline turning a host/service/vuln spec into a
  Dockerfile layer set; a small catalog of base service images (vulnerable web
  app, SSH host with weak creds, internal file server, a minimal "kali" attacker
  image); a **vuln/flag injection** mechanism (planted `is_flag` files; weak creds
  from `identities`; misconfigs from `service.config`); **content-addressed image
  caching** keyed by resolved build inputs; **digest pinning** on output.
- Wire `build_images(scenario)` into the provision path (the Docker backend uses
  the resulting digests).

## Out of scope

- Windows images (future, B-11); a production-grade vuln library / full pentest
  toolset (future fragments, B-14/B-15); a shared image **registry** (OCIR is
  backlog B-31 — v1 caches locally).

## Deps introduced this step

None beyond `docker` (build via the SDK). Pinned base images referenced by digest.

## Implementation details

- **Build pipeline**: resolve each host's image spec → a layer set (base image by
  digest + service install + injected artifacts). Builds are **hermetic**: no
  network at build unless explicitly allowlisted; pin apt/pip versions (vendored
  cache where feasible) so rebuilds are deterministic.
- **Catalog** (minimal, expand later): a vulnerable web app, an SSH host with weak
  creds, an internal file server, and a minimal attacker image (bash, python,
  nmap, curl). The full toolset is a future fragment (B-14).
- **Injection**:
  - **Flags** — generated **deterministically** from `(scenario_id, flag_id,
    seed)` so re-provisioning yields identical flags (stable scoring) unless
    `rotate_flags` is set. Planted at the `FileArtifact.path` with its `mode`.
    **Export the flag-generation function — the scorer (3.3) imports the same
    one.**
  - **Weak creds** — from `identities` (resolve `secret_ref` to a generated weak
    secret) baked into the host.
  - **Misconfigs** — from `service.config`.
- **Cache**: key = `sha256(base digest + ordered layer inputs)`. A cache hit
  **skips rebuild**. Output images are referenced **by digest** downstream (D7).

## Infrastructure (Terraform)

- **No new OCI resource for v1.** Golden images build and cache **locally** on the
  0.3 host's Docker image store (on the attached block volume). That is the
  KISS/YAGNI choice for a single host.
- A shared **OCI Container Registry (OCIR)** repo — so images are built once and
  pulled by many hosts/workers — is **backlog B-31**, triggered by the move to
  multiple hosts (Epic 7 / cloud backend). Do **not** add it now.
- Watch disk: image layers live on the block volume; if builds outgrow it, bump
  `block_volume_gb` in `deploy/terraform/variables.tf` and `make tf-apply`
  (surgical) — otherwise leave it.
- `@pytest.mark.docker` build tests run on the OCI host.

## Contracts produced

`build_images(scenario) -> {host_id: image_digest}`; the **deterministic
flag-generation function** (shared with the scorer, 3.3); the content-addressed
cache convention.

## Testing

**Unit (`test_images.py`, runs in CI):**
- Cache-key stability: same inputs ⇒ same key; any input change ⇒ different key.
- **Deterministic flag generation**: `(scenario_id, flag_id, seed)` ⇒ identical
  flag value across calls; `rotate_flags` changes it.

**Integration (`@pytest.mark.docker`, on the OCI host):**
- Build the reference range's images; a planted flag is present at its path with
  the right mode; the weak credential logs in; a **cache hit on rebuild** rebuilds
  no layers (assert via build output / timing).

## Engineering standards

All of `_SHARED_STANDARDS.md`. Images are pinned by digest downstream (D7); builds
hermetic and reproducible. The flag function is the single source of truth for
both planting and scoring — comment that contract explicitly.
