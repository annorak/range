# Step 3.2 — Attacker agent: ReAct, toolbox, compaction  `[MVP]`

> **Claude Code session prompt.** Self-contained. Read

## Session context

The Inspect bridge (3.1) makes a Range scenario runnable and routes tool calls
into the range. This step writes the **attacker agent**: a ReAct (reason → act →
observe) solver with a real toolbox (`bash`, `python`, multi-host `run_on`,
`submit_flag`) and **context compaction** so long runs don't blow the model
window. The agent is model-agnostic (any Inspect-supported provider) and stateless
across runs — all state lives in the Inspect store/trace.

## Goal

The attacker autonomously progresses a range and emits clean, structured
tool-call events.

## Scope (build this)

- `agents/attacker.py`: a ReAct solver built on Inspect's agent/tool primitives;
  configurable model + token budget.
- `agents/tools.py`: tools — `bash`, `python`, `run_on(host_id, cmd)` (multi-host
  exec through the sandbox), and `submit_flag(flag)`.
- `agents/compaction.py`: context compaction at ~80% of the window
  (summarize-and-continue, **retaining credentials / topology / progress**).

## Out of scope

- Defender (5.2), user-sim (5.3), inter-agent policy (5.4); scoring (3.3); the
  end-to-end `range run` (3.4).

## Deps introduced this step

None beyond `inspect-ai` (from 3.1).

## Implementation details

> As in 3.1, **conform to the pinned Inspect version's** agent/solver/tool APIs;
> the shapes below describe intent — match the installed package.

### `agents/tools.py`
- Each tool is an Inspect `@tool` that calls the active `RangeSandbox`:
  - `bash(cmd, timeout=...)` → sandbox `exec(["bash","-lc",cmd])` on the entry
    host.
  - `python(code, timeout=...)` → sandbox `exec(["python3","-c",code])`.
  - `run_on(host_id, cmd, timeout=...)` → multi-host exec: route to
    `Backend.exec(handle, host_id=host_id, ...)` via the sandbox (this is the
    multi-host capability 3.1 deferred to here). Validate `host_id` is in the
    range; an unknown host returns a clean tool error, not an exception.
  - `submit_flag(flag)` → records a flag submission (consumed by the scorer 3.3);
    returns whether it was accepted **without leaking** the correct value.
- **Every tool emits a structured tool-call event** to the injected trace sink
  (consumed by 4.3): correlation IDs + tool name + args (redacted) + result
  summary. Keep the event shape aligned with the trace schema (4.1) — reference
  it, don't reinvent.

### `agents/attacker.py`
- A ReAct solver: system prompt frames the objective (from the sample metadata),
  exposes the toolbox, loops reason→act→observe until the objective is met, the
  **token budget** is exhausted, or a max-steps cap is hit.
- **Model-agnostic**: the model is a parameter (any Inspect provider). Default
  from config; overridable per run (3.4 passes `--model`).
- **Token budget**: enforced; on exhaustion the run **ends cleanly with a partial
  result** (no exception). Record budget-exhaustion as a trace event.
- **Stateless across runs**: no module/global state; all run state in the Inspect
  store/trace.
- Keep the scaffold **minimal and reproducible** (per published range practice) —
  no elaborate planner; fancy scaffolds are a future experiment (backlog area).

### `agents/compaction.py`
- Trigger when context usage crosses ~80% of the model window.
- **Summarize-and-continue**: replace older turns with a structured summary that
  **must retain** discovered credentials, the network/topology map, and progress
  toward milestones; keep recent turns verbatim.
- Each compaction is recorded as a **trace event** (so replay shows where it
  happened). Make the retention set explicit and tested.

## Infrastructure (Terraform)

- **No new OCI resource.** The agent runs in the control-plane process on the 0.3
  host and reaches model providers over the already-permitted 443 egress; API
  keys come from `config.Settings` (see 3.1's infra note; managed secrets are
  backlog **B-34**). Range containers stay egress-denied — only the agent process
  calls models.
- All 3.2 tests use the **fake backend + a mock model**, so they run in CI with no
  host and no real API spend. (Real-model runs happen in 3.4 on the host.)

## Contracts produced

## Testing

**Unit (fake backend + mock model — runs in CI, no API spend):**
- *attacker*: with a **mock model** returning canned tool calls, the agent solves
  a scripted 2-step toy range **deterministically** (recon → read flag →
  `submit_flag`); the run ends with a partial result when the **budget is
  exhausted** (no raise).
- *tools*: `bash`/`python`/`run_on` route to the correct host via the sandbox;
  `run_on` with an unknown `host_id` returns a clean tool error; `submit_flag`
  doesn't leak the correct value; each tool emits a well-formed tool-call event.
- *compaction*: crossing the threshold triggers compaction; the summary
  **retains** credentials/topology/progress (assert specific facts survive); a
  compaction event is emitted.
