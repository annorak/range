# Step 2.3 — Network fabric: subnets, routing, firewall, egress  `[MVP]`

> **Claude Code session prompt.** Self-contained. Read
> `docs/steps/_SHARED_STANDARDS.md` first.

## Session context

Hosts run as containers (2.2), but flat — no subnets, no controlled reachability,
and (dangerously) no egress control. This step builds the **network fabric**: a
Docker network per subnet, a router bridging them with per-edge allow/deny policy
from the spec, **default-deny internet egress** with an optional per-scenario
allowlist, and in-range DNS so hosts resolve each other by name. This is what
makes a range a realistic multi-subnet environment instead of a bag of containers.

⚠️ **Known sharp edge (backlog B-30):** Docker's embedded DNS resolver
(`127.0.0.11`) on user-defined bridge networks **does not work under `runsc`**.
Validate name resolution **early** in this step and pick a workaround (router-based
resolver, hosts-file injection, or `--link`-style wiring). Don't discover this in
2.4.

## Goal

The reference topology's reachability matrix matches the spec, name resolution
works, and internet egress is closed by default.

## Scope (build this)

- `provision/network.py`: create a Docker network **per subnet** (never the
  default bridge); attach hosts to their subnet(s) with **static IPs** (for
  determinism); stand up a **router container** that bridges subnets with
  `iptables` forwarding + per-edge allow/deny from the spec; **default-deny
  egress** to the internet with an optional per-scenario allowlist; in-range DNS
  resolving `host_id` → IP.
- Wire this into `DockerBackend.provision` (networks created before containers
  attached; torn down with the run by label).

## Out of scope

- eBPF policy (future, backlog B-13); network *telemetry* capture (4.5); gVisor
  hardening (2.4).

## Deps introduced this step

None beyond `docker` (already added in 2.2). The router uses a minimal existing
base image.

## Implementation details

- **Per-subnet networks**: one Docker network per `Subnet`, created with the
  subnet's CIDR and `internal: true` **unless** the scenario allowlists egress.
  Label with the run IDs for cleanup.
- **Static IPs**: assign each host a deterministic IP within its subnet (derived
  from a stable ordering / the seed) so reachability and traces are reproducible.
- **Router container**: a minimal image with IP forwarding enabled; attached to
  every subnet; `iptables` FORWARD rules generated from the **spec's edge policy**
  (which subnet/host pairs may talk). Routes derived from the subnet graph.
- **Egress**: default-deny to the internet. If the scenario declares an egress
  allowlist, implement it as explicit `iptables`/proxy rules on the router; record
  that **egress is open** on the run record (§8 safety flag).
- **DNS**: provide name resolution for `host_id` → IP. Because embedded DNS is
  broken under `runsc` (B-30), implement resolution via the **router as a small
  resolver** (or inject `/etc/hosts` entries at container creation). Pick one,
  document it in ADR 0004, and make it work under `runsc` (verify in the
  integration test, not just on the default runtime).
- Extend `RangeHandle.network` (`NetworkInfo`) with the subnet map + per-host IPs
  so the orchestrator/agents and the trace layer can use them.

## Infrastructure (Terraform)

No **new** OCI resource. Notes:
- The **host NSG stays locked** (from 0.3): the range's containers must not reach
  the host's other interfaces or the internet — that isolation is enforced
  **in-Docker** here (`internal` networks + router egress rules), *separate* from
  the host firewall. Do not loosen the OCI NSG to make a range "work"; fix it in
  the Docker network policy.
- If you add an egress *proxy* image for allowlisted scenarios, it runs as a
  container on the host — still no OCI change.
- Run the `@pytest.mark.docker` reachability tests on the OCI host (they need
  `runsc` to catch the DNS edge).

## Contracts produced

`NetworkInfo` in `RangeHandle` (subnet map, host IPs); the egress policy applied +
recorded; the DNS-resolution mechanism that works under `runsc`.

## Testing

**Unit (`test_network.py`, runs in CI):**
- Route/rule generation from a topology graph: correct routes per subnet edge;
  firewall rules match the spec's allow/deny edges; static-IP assignment is
  deterministic for a given scenario + seed.

**Integration (`@pytest.mark.docker`, on the OCI host under `runsc`):**
- Same-subnet hosts reach each other; cross-subnet only where policy allows;
  **internet blocked by default**; an allowlisted destination is reachable;
  **name resolution works** (the B-30 workaround is proven here).
- Teardown removes all networks + the router by label (no leaks).

## Engineering standards

All of `_SHARED_STANDARDS.md`. Egress-open scenarios **must** set the run-record
safety flag. Document the DNS workaround in ADR 0004. Comment the *why* on the
`internal`-network default and the router rule generation.
