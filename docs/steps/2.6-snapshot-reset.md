## Session context

A range can be provisioned, networked, hardened, and built from golden images
(2.2–2.5). To run the **same range many times** — for A/B arms and statistically
powered campaigns — we need to **reset it to a byte-identical starting state**
cheaply, instead of a full reprovision each time. This step implements
`snapshot`/`restore`/reset for the Docker backend with a **tested determinism
guarantee**.

## Goal

Repeated runs start from a verified-identical state; 10× reset yields the same
flags + topology; resets are parallel-safe.

## Scope (build this)

- Implement `snapshot`/`restore` on `DockerBackend`: prefer a **fast
  "rebuild-from-golden + state-overlay" reset** (cheap, deterministic) over
  `docker commit` where possible; commit-based snapshots only for genuinely
  stateful hosts; snapshots store **only divergent state**.
- A `range reset` capability (used by A/B in 6.2 and parallel runs in 7.x).
- Concurrency-safe via per-handle locks.

## Out of scope

- VM snapshots (future backend); the A/B harness itself (6.2) and the parallel
  controller (7.x) — this step provides the primitive they consume.

## Implementation details

- **Reset strategy**: rebuild-from-golden is the default — tear down the
  containers, re-create from the (cached, digest-pinned) golden images, re-apply
  the network + hardening, and **re-seed RNG-derived artifacts identically** so
  flags/configs are byte-identical. This is cheap because images are cached (2.5)
  and deterministic by construction.
- **Snapshots for stateful hosts**: where a host accumulates state that must be
  captured (not just rebuilt), `docker commit` that container and store the
  resulting image digest as the `SnapshotId`; `restore` re-creates from it.
  Snapshots record **only divergence** from the golden baseline.
- **Determinism guarantee**: `restore`/reset yields a byte-identical starting
  state for scoring purposes — this is a **tested** property, not a hope.
- **Concurrency**: per-`RangeHandle` locks so parallel resets (different arms)
  don't interfere; idempotent.

## Infrastructure (Terraform)

- Container snapshots are **Docker-level** (commit/rebuild) — no OCI resource.
- *Optional* hardening: add an `oci_core_volume_backup_policy` on the 0.3 block
  volume so the host's persistent **state/trace** data is snapshotted on a
  schedule. This is a small, optional Terraform addition; gate it behind a
  default-off variable (`enable_volume_backups`) and document it. It is **not**
  what range-reset uses (that's Docker-level) — it's disaster-recovery for the
  host's data disk. Keep it out unless you actually want it (YAGNI).
- `@pytest.mark.docker` snapshot tests run on the OCI host.

## Contracts produced

Reliable `snapshot`/`restore`/reset semantics with a determinism guarantee —
relied on by A/B (6.2) and parallel runs (7.x).

## Testing

**Unit (`test_snapshot_unit.py`, runs in CI):**
- Reset planning: chooses rebuild-from-golden vs commit per host correctly;
  per-handle lock prevents concurrent reset of the same range; reset re-seeds
  artifacts deterministically (assert the planned flag set is identical).

**Integration (`@pytest.mark.docker`, on the OCI host):**
- `snapshot` → mutate a host → `restore` → state matches the snapshot.
- **10× reset** of the reference range yields an **identical flag set + topology**
  every time (the determinism guarantee).
- Parallel resets of two ranges don't interfere (run under `asyncio.gather`,
  assert both end in correct independent states).
