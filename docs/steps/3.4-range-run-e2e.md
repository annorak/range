## Session context

## Goal

One command runs a real range attack and produces a **scored, traced, torn-down**
result.

## Implementation details

### `run/single.py` — the pipeline (strict ordering, guaranteed teardown)
```python
async def run_single(scenario, *, model, seed, budget, backend, keep=False) -> RunResult:
    ids = CorrelationIds(run_id=new_run_id(), scenario_id=compute_scenario_id(scenario), ...)
    # 1. validate (reject invalid specs before spending compute)
    diags = validate(scenario)
    if has_errors(diags): raise RunError("run.invalid_spec", hint=...)
    # 2. open trace (run_id) + start host-telemetry collectors (4.4)
    # 3. build images (2.5) -> digests
    # 4. provision (2.x) -> RangeHandle
    handle = None
    try:
        handle = await backend.provision(scenario, run_ctx)
        # 5. run the Inspect attacker eval (3.1 task + 3.2 solver + 3.3 scorer)
        #    model trace captured by 4.3, host telemetry by 4.4 -> unified store (4.2)
        result = await _run_eval(scenario, handle, model=model, budget=budget, ...)
        # 6. assemble RunResult (3.3) incl. cost (tokens + wall + per-host seconds)
        # 7. persist RunResult to the trace store (4.2)
        return result
    finally:
        # 8. ALWAYS teardown (unless --keep); flush + close the trace
        if handle is not None and not keep:
            await backend.teardown(handle)
```
- **The run is the transaction.** A partial failure still tears down **and** still
  persists a `RunResult` with `status="failed"`/`"error"` (don't lose the
  evidence). Use `try/finally`; teardown is idempotent (2.2).
- **Correlation IDs threaded everywhere** so the model trace, host telemetry,
  lifecycle, and score events all land on **one timeline** keyed by the same
  `run_id` (§8).
- **Cost**: record tokens (from the eval), wall time, and per-host seconds into the
  `RunResult` + as trace metrics.
- **Determinism**: same scenario + seed + (mock) model ⇒ identical flags,
  topology, and replay ordering (the e2e determinism test).

### `cli` — `range run`
```python
@app.command()
def run(
    scenario: Path = typer.Argument(..., exists=True, readable=True),
    model: str = typer.Option(..., "--model"),
    seed: int = typer.Option(0, "--seed"),
    budget: int | None = typer.Option(None, "--budget", help="Token budget."),
    backend: str = typer.Option("docker", "--backend", help="docker|fake"),
    keep: bool = typer.Option(False, "--keep", help="Skip teardown (debug)."),
) -> None:
    """Provision, attack, score, and tear down a range in one run."""
    # CLI reads the file (spec stays pure), resolves the backend from the registry,
    # runs the pipeline, prints the summary, exits with a status-derived code.
```
- The **summary** prints: milestones reached (of total), credited flags, score,
  cost (tokens + wall + per-host seconds), `status`, and a **pointer to the run's
  trace** (so `range trace` / replay from 4.6 can open it).
- **Exit code** reflects `RunResult.status` (0 for completed, non-zero otherwise).

## Testing

**E2E (`tests/e2e/test_range_run_fake.py`, fake backend + mock model — runs in CI):**
- `range run` on a toy scenario → a `RunResult` **and** a **queryable trace**
  (model + host + lifecycle + score events on one timeline, joinable by `run_id`).
- **Teardown always**: with the fake backend, assert the range is torn down after a
  normal run and after a forced mid-run failure (which still persists a failed
  `RunResult`).
- **Determinism**: same scenario + seed + mock model ⇒ identical flags, topology,
  and event ordering across two runs.
- `--keep` skips teardown; exit code matches status.

**E2E (`@pytest.mark.docker`, on the OCI host):**
- `range run --backend docker` on a **2-host** range: a real attack progresses,
  produces a scored `RunResult`, a populated trace, and **zero leaked resources**
  after teardown (label-verified).
