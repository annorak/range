## Implementation details

### `pyproject.toml`
- Build backend: `hatchling`. `project.name = "range-lab"`, `requires-python =
  ">=3.12"`, dynamic or static `version` (e.g. `0.0.1`).
- **Runtime deps (only what this step imports):** `typer>=0.12`. *(Feature deps —
  pydantic, structlog, ruamel.yaml, etc. — are added by the steps that introduce
  them.)*
- **Dev deps** (a `[dependency-groups]` `dev` or `[tool.uv]` dev group): `ruff`,
  `mypy`, `pytest`, `pytest-cov`, `pytest-asyncio`, `hypothesis`, `import-linter`,
  `pre-commit`.
- `console_scripts`: `range = "rangelab.cli.main:app"`.
- Configure tools in-file:
  - `[tool.ruff]` line-length 88; a sensible rule set (`E`, `F`, `I`, `UP`, `B`,
    `SIM`, `RUF`); `[tool.ruff.format]` defaults.
  - `[tool.mypy]` `strict = true`, `python_version = "3.12"`, `mypy_path =
    "src"`, packages = `rangelab`.
  - `[tool.pytest.ini_options]` `testpaths = ["tests"]`, `addopts =
    "--cov=rangelab --cov-report=term-missing --cov-fail-under=90"`, and
    **register markers** `docker` and `postgres` so unmarked CI never tries to
    run them.
  - `[tool.coverage.run]` `source = ["src/rangelab"]`, `branch = true`.

### import-linter
Encode the §6 boundaries now (most packages are empty, but the architecture is
locked from commit 1). Put under `[tool.importlinter]`:

```toml
[tool.importlinter]
root_package = "rangelab"

[[tool.importlinter.contracts]]
name = "Layered architecture — no upward imports"
type = "layers"
# Highest layer first; a layer may import any layer BELOW it, never above.
layers = [
    "rangelab.cli",
    "rangelab.run",
    "rangelab.report",
    "rangelab.orchestrator",
    "rangelab.agents",
    "rangelab.inspect_bridge",
    "rangelab.provision",
    "rangelab.scoring",
    "rangelab.trace",
    "rangelab.spec",
    "rangelab.config",
    "rangelab.common",
]

[[tool.importlinter.contracts]]
name = "provision and trace are independent"
type = "independence"
modules = ["rangelab.provision", "rangelab.trace"]
```

> Note on `config`: `config` may import `common` only; nothing else imports
> *into* config that would form a cycle. The layering above places `config` just
> over `common`, so `config → common` is allowed and `config → anything-higher`
> is forbidden, which matches §6. This sharpens the doc's "common and config
> depend on nothing internal" to "they sit at the bottom; config may use common."
> Capture that one-liner in an ADR (`docs/adr/0002-...md`) if you want, optional.

### `cli/main.py`
```python
"""The `range` command. Subcommands are added by later steps."""
import importlib.metadata
import typer

app = typer.Typer(no_args_is_help=True, add_completion=False)

def _version_cb(value: bool) -> None:
    if value:
        typer.echo(importlib.metadata.version("range-lab"))
        raise typer.Exit()

@app.callback()
def main(
    version: bool = typer.Option(
        False, "--version", callback=_version_cb, is_eager=True,
        help="Show the Range version and exit.",
    ),
) -> None:
    """Range — declarative, ephemeral cyber ranges."""
```

`src/rangelab/__init__.py` sets `__version__ = importlib.metadata.version("range-lab")`
(or a static string matching pyproject — pick one source of truth; metadata is
cleaner).
