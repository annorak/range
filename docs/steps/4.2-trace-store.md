## Session context

The trace schema exists (4.1). This step makes it **durable**: a `TraceStore`
interface + a `ParquetPostgresStore` implementation that flushes partitioned
Parquet (events) and indexes runs in Postgres (metadata + pointers), plus
`RunResult` persistence. `TraceStore` is the single injected seam for all
persistence (D5/D8), so ClickHouse/Kafka can replace the impl later without
touching callers.

## Goal

Events persist (append-only Parquet), the run index is queryable (Postgres), and
the impl could be swapped for ClickHouse without changing any caller.

## Scope (build this)

- `trace/store.py`: the `TraceStore` interface + `ParquetPostgresStore` impl —
  buffered Arrow writers flushing partitioned Parquet (to the block volume by
  default, or S3-compatible object storage via `s3fs`); a Postgres schema via
  **`alembic`** migrations; `append`, `get_run`, `list_runs`, `save_result`.
- `deploy/compose/services.yml`: the **on-host Postgres** service (the new
  services layer).
- `deploy/terraform/`: an **optional, gated** OCI Object Storage bucket for
  Parquet/PCAP blobs.

## Implementation details

### `trace/store.py`
```python
class TraceStore(Protocol):
    async def append(self, events: Sequence[Event]) -> None: ...   # append-only
    async def get_run(self, run_id: str) -> RunMeta | None: ...
    async def list_runs(self, *, limit: int = 50, ...) -> list[RunMeta]: ...
    async def save_result(self, result: RunResult) -> None: ...
    async def open_run(self, ids: CorrelationIds, scenario: Scenario) -> None: ...
    async def close_run(self, run_id: str) -> None: ...            # flush + finalize
```
- **`ParquetPostgresStore`**:
  - Buffers events by `(run_id, source)`; **flushes on size or time** to a Parquet
    part at `partition_path(...)` (4.1 layout). **Idempotent part naming**
    (monotonic seq per `(run_id, source)`) → exactly-once-ish on retry; **never
    mutate a written part** (append-only).
  - **Filesystem abstraction**: write via a `fsspec`/`s3fs` handle so the *same
    code* targets the local block-volume path (default) or the object-storage
    bucket (when `Settings` provides an `s3://…` root + endpoint). KISS: one
    writer, two backends by URL.
  - Postgres holds **metadata + pointers only** (cheap, scalable index); bulky
    events stay in Parquet.

### `trace/models_sql.py` + migrations
SQLAlchemy 2.0 tables; alembic migrations (up/down clean):
- `runs(run_id pk, scenario_id, model, status, started_at, ended_at, cost_usd, ...)`
- `scenarios(scenario_id pk, name, content_hash, ...)`
- `events_index(id pk, run_id fk, source, t_min, t_max, count, parquet_path)` —
  one row per flushed part, so a query planner can prune by run/source/time.
- `run_results(run_id pk fk, json payload of RunResult, score, milestones, ...)`

### Config
Extend usage of `Settings` (0.2): `postgres_url` (points at the compose Postgres),
`trace_dir` (block-volume path, default), and **new** optional
`trace_blob_root` (`s3://range-trace-…`) + `s3_endpoint_url` for object storage.
When `trace_blob_root` is unset → local Parquet under `trace_dir`.

## Infrastructure (Terraform + compose)

This is the step that pins down on-host persistence. Two layers, each doing what
it's best at:

**1. On-host services → docker-compose (`deploy/compose/`) — NEW layer.**
- `services.yml` defines **Postgres** (pinned image by digest) with its data dir on
  the **0.3 block volume** (`/data/postgres`), `POSTGRES_*` from a git-ignored
  `.env` (commit `.env.example`), bound to **localhost only** (no host-port exposed
  to the world; the NSG already blocks it, but bind to `127.0.0.1` as defense in
  depth). The operator runs `docker compose -f deploy/compose/services.yml up -d`
  on the host (add a `make services-up` / `services-down` target).
- **Why compose, not Terraform, for Postgres:** Postgres is an *on-host container*,
  not an OCI cloud resource. Terraform owns OCI infra (VM/network/volume/bucket);
  compose owns long-lived on-host service containers. This keeps each declarative
  and avoids the Terraform-docker-over-SSH provider. Promoting to **OCI managed
  PostgreSQL** is backlog **B-35**.

**2. Blob store → Terraform OCI Object Storage (optional, gated).**
- `storage.tf`: an `oci_objectstorage_bucket` **gated** behind
  `var.enable_object_storage` (default **false**). When false, Parquet writes to
  the block volume (the v1 demo default — simplest, no credentials). When true,
  the bucket holds Parquet + PCAP blobs and the store targets it via `s3fs`.
  ```hcl
  data "oci_objectstorage_namespace" "ns" { compartment_id = var.compartment_ocid }
  resource "oci_objectstorage_bucket" "trace" {
    count          = var.enable_object_storage ? 1 : 0
    compartment_id = var.compartment_ocid
    namespace      = data.oci_objectstorage_namespace.ns.namespace
    name           = "range-trace-${var.env}"
    freeform_tags  = local.common_tags
  }
  ```
- Output the **S3-compatible endpoint**
  (`https://<namespace>.compat.objectstorage.<region>.oraclecloud.com`) so `s3fs`
  can use it. **Object-storage credentials (Customer Secret Keys) are supplied
  out-of-band** (env/secret), never in TF state. Defaulting to local Parquet is the
  "good enough for now" choice → backlog **B-36** (object storage as default + a
  lifecycle/retention policy).

**Testing infra:** `@pytest.mark.postgres` tests run against the compose Postgres
(on the host, or any machine running `services.yml`); they **skip** when no
Postgres is reachable. Local-Parquet unit tests run anywhere (fake fs).

## Testing

**Unit (`test_store_buffering.py`, fake filesystem — runs in CI):**
- Buffering/flush: events batch by `(run_id, source)`; flush triggers on
  size/time; part naming is idempotent (a retried flush doesn't duplicate or
  mutate parts); written parts are never re-opened for write.

**Integration (`@pytest.mark.postgres` + local Parquet):**
- Append N events across multiple sources → query the index (`events_index`
  rows + counts correct) → read the Parquet parts back losslessly.
- **Concurrent appends** from multiple sources don't corrupt the buffers or the
  index (run under `asyncio.gather`).
- `save_result`/`get_run`/`list_runs` round-trip a `RunResult`.
- Alembic migrations apply **up and down** cleanly.

## Engineering standards

All of `_SHARED_STANDARDS.md`. **Append-only — never mutate a written part.**
`TraceStore` is injected everywhere (so ClickHouse is a drop-in). Secrets
(`POSTGRES_*`, object-storage keys) never in VCS/images/TF state. Pinned Postgres
image by digest. Comment the *why* on idempotent part naming and the
single-writer/two-backends design.
